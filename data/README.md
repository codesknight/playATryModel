# 语料与清洗结果

## 来源记录

学习者采集并核对了四份中文小说文本，提供的来源线索为：

https://github.com/weiyinfu/SiDaMingZhu/tree/master/src

文件名为三国演义.txt、水浒全传.txt、红楼梦.txt、西游记.txt。本记录说明学习者提供的来源，不声称本地文件与上游某一提交逐字一致，也未核验上游版本完整性和许可。此目录不包含笔记中另行收藏的中英对照语料。

## 目录

- `corpus/`：原始采集文本，不由清洗脚本覆盖。
- `corpus_processed/`：第二课生成的 UTF-8 文本，保留每本书的独立文件。
- `chapters/chapters.jsonl`：第四课生成的 460 条章节记录，每一物理行是一章的 JSON 表示。
- `splits/`：第五课按整章划分的训练、验证、测试集，以及 manifest.json 复现清单。
- `vocab/vocab.json`：第六课仅由训练集建立的有序字符词表及训练来源指纹。

在项目根目录运行：

```powershell
python scripts/learn/01_inspect_data.py # 检查原始文本的路径、开头和字符统计。
python scripts/learn/02_clean_data.py # 删除空白行和每行首尾空白，重新生成清洗结果。
python scripts/learn/03_split_chapters.py # 切分完整章节，保存 JSONL，并读取回来检查内容一致。
python scripts/learn/04_split_dataset.py # 按书随机划分完整章节，保存三个集合及其指纹清单。
python scripts/learn/05_build_vocab.py # 建立训练字符词表，验证编码解码，并统计验证集未知字符。
```

清洗保留正文、标点、标题和行内空格。第五课已划分训练集、验证集和测试集，尚未将这四份语料用于模型训练。

第三课 `scripts/learn/03_split_chapters.py` 完成章节识别与内存中的切分：四本书分别得到 120、120、120、100 章，合计 460 章。各书章节顺序拼接后与清洗文本完全一致。第四课在同一脚本中增加 JSONL 保存与重载验证。

## 章节记录格式

每条记录包含 `id`、`book`、`chapter_index` 和 `text`。id 由书名和至少三位的切分顺序号组成，例如 `三国演义:001`；chapter_index 是切分顺序，不表示已经校验标题中的真实回数。text 保留完整章节，包含标题和正文。

正文换行由 JSON 转义表示，不会把一条记录拆成多行；使用 json.loads 后还原成真正的换行。数据采用 UTF-8 和 LF 保存，无缩进。当前文件 9,258,686 字节，460 个物理行，ID 唯一，重载后记录顺序、字段和正文均与保存前一致。

## 第二课结果

统计值按 Python 读取并统一换行后的字符串长度计算，不是文件字节数。

| 文件 | 原始字符数 | 清洗后字符数 | 减少 |
| --- | ---: | ---: | ---: |
| 三国演义.txt | 599,460 | 597,979 | 1,481 |
| 水浒全传.txt | 900,163 | 897,427 | 2,736 |
| 红楼梦.txt | 865,713 | 864,306 | 1,407 |
| 西游记.txt | 720,681 | 718,733 | 1,948 |
| 合计 | 3,086,017 | 3,078,445 | 7,572 |

Git 将文本换行统一为 LF。本地 Windows 上 write_text 默认可能写为 CRLF，因此文件字节数与清洗后的字符数变化不必一致。

## 第五课：固定的章节划分

每本书内先按章节顺序号和 ID 排序，书籍按文件名排序，使用局部 random.Random(42) 打乱章节列表，再按章节数约 80%/10%/10% 划分，测试集取剩余部分。正文及章节内部字序不变。

| 集合 | 章节数 | 正文字符数 |
| --- | ---: | ---: |
| train | 368 | 2,456,586 |
| validation | 46 | 317,717 |
| test | 46 | 304,142 |

三份文件的章节 ID 两两互斥，覆盖全部输入章节，没有完全相同的整章正文跨集合；这不排除重复段落或相似句子。所有重载记录与原始章节记录一致。重复运行和打乱输入记录排列后，输出划分保持一致。

manifest.json 记录种子、算法标识、比例、源文件 SHA-256、各集合的计数和文件指纹。正式对比模型时冻结这三个文件，不依据测试集结果调整划分。当前测试目标为同四本书的留出章节，不代表真实部署中其他题材的泛化能力。

## 第六课：字符词表

训练集共有 5,546 种字符，预留编号 0 对应特殊符号 <UNK>，词表共 5,547 项。普通字符排序后确定编号，词表顺序不能在模型训练后随意更改。vocab.json 保存 type、unk_token、unk_id、tokens 和 train_sha256。

词表未从验证集或测试集收集字符。验证集有 68 种未见字符，共出现 102 次，占 317,717 个字符约 0.0321%。该指标只反映字符覆盖，不衡量模型生成能力。

全部训练正文编码后可逐字解码还原；未见字符统一映射到 0，只能解码为 <UNK>，无法恢复原字。词表保存重载与重复运行的字节一致性均通过检查。当前是字符级 tokenization，不依赖中文词级分词。
