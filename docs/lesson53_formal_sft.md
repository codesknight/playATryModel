## Block 3：新阶段如何更新

train_chat_sft.py载入model/lesson50/last_train.pt的FP32模型矩阵；预训练累计2020步保持原记录。SFT改变训练目标，明确新建AdamW，不恢复旧预训练优化器历史：学习率0.00005、betas=(0.9,0.95)、weight_decay=0.01。

每个微批2条会话，累积4微批后更新一次，即一次更新8条会话。输入右填PAD=0，标签填-100，只监督助手正文和结束符。与第五十一课相同，按整组有效助手目标数归一：

```python
loss = F.cross_entropy(model(x).flatten(0, 1), y.flatten(), ignore_index=-100, reduction="sum") / positions  # positions是本累积组所有微批的有效目标总数。
scaler.scale(loss).backward()  # 四个微批分别反向，但累积组结束前不更新参数。
```

AMP使用FP16 autocast、FP32主参数与GradScaler初值1024；unscale后统一全局范数裁剪1.0，每组只step一次。发生溢出重试同一组，成功才推进游标。本次跳过0。随机排列由553+轮号重建，轮末不重置模型或AdamW。

预先固定在SFT步0、100、200、350、500验证及生成；旧起点也参与最佳选择。阶段计时从起点验证前开始，包含周期验证、生成和保存，在累积组边界检查900秒；文件加载在阶段计时前，截止后的必要收尾和导出另计，不是进程硬截止。本次先达到500步，没有增加预算、没有追加新正式更新。

正式SFT共见85388个助手目标，游标epoch34/offset22，即4000条会话曝光=500×8=34×117+22。117行数据已被反复遍历约34轮，数量少时快速过拟合并不意外；不能将4000次曝光称为4000个独立样本。
