## Block 2：输入是什么

代码入口为scripts/experiments/sft_batches.py，先阅读encode_dialogue。真实模板为：

```text
<|bos|><|user|>问题<|end|><|assistant|>回答<|end|>
```

用户、助手和结束符分别是专用编号4、5、6。正文通过原BPE编码，不能按字符长度填监督标记；一个中文词可能合并成token，表情也可能拆成多个token。末尾不额外插入EOS，助手结束符6就是本课回答的停止目标。多轮对话按同一模板连续保留。

```python
body = tokenizer.encode(content, add_special_tokens=False).ids  # 用真实BPE获取正文编号。
ids.extend([SPECIAL[role], *body, SPECIAL["end"]])  # 保留角色、正文及消息结束符。
flags.extend([False, *([role == "assistant"] * len(body)), role == "assistant"])  # 只标记助手正文和结束符。
```

上述片段位于消息循环中，不能脱离role/content/tokenizer等已有变量直接单独运行。完整可运行代码每个非空行都有直白注释。

## Block 3：输入和目标一起错一位

```python
x = ids[:-1]  # 用当前token预测下一个。
y = [token if keep else -100 for token, keep in zip(ids[1:], flags[1:])]  # 下一token与它的监督标记必须一同移位。
```

读取assistant角色头的位置，目标是回答首token，因此回答首token也会被学习。用户问题、角色头、用户结束符等目标为-100，但对应输入都保留。模型内部的因果注意力仍可读取当前位置及前文；这里没有用-100修改输入token。

最长上下文仍256。本课超长完整对话直接拒绝，不通过截掉末尾答案凑长度，也不把被截断的句子伪装成完整回答。后续扩大数据前另行设计按完整轮次构造样本、长回答处置和覆盖统计。

## Block 4：不同长度如何组成批次

两条会话输入长度104、197，助手目标数84、165。右侧填充后X/Y均为(2,197)：输入填0，标签填-100。因为有效输入都在PAD之前、模型使用因果注意力，右侧PAD不会影响前面有效位置；填充位置的输出也没有直接损失。本课未采用左填充或跨对话打包，不能将这个结论套用到其他布局。

分数logits形状为(2,197,6400)，交叉熵前变成(394,6400)，目标变成(394)。有效分母为249，而非394，也不是先求两条会话均值再简单平均：

\[
L=\frac{\sum_{b,t:\;y_{b,t}\ne-100}-\ln p_{b,t}(y_{b,t})}{84+165}
\]

```python
loss = F.cross_entropy(logits.reshape(-1, 6400), y.reshape(-1), ignore_index=-100, reduction="sum") / 249  # 按本批全部有效助手目标求平均。
```

249是本次真实目标数，正式函数从y动态计数，不写死任何批次的分母。后续微批累积也应以累积组的有效助手目标总数归一化。

## Block 5：真实单步，验证训练流程

实际入口scripts/experiments/probe_sft_step.py从第五十课完整FP32参数构造独立副本，保持词表和网络结构。预先限制最多一次更新、训练计算120秒；超时检查在step之前，文件加载与模型构造另计，不是进程硬截止。当前卡实际运行FP32，不使用AMP，便于直接观察梯度。

这里是新的SFT诊断目标，明确新建AdamW：学习率0.00001，betas=(0.9,0.95)，weight_decay=0.01，统一梯度裁剪1.0。它有意重置优化器历史，与上一课“原目标原轨迹完整续训”含义不同；不能把这个优化器t=1冒充原预训练t=2021。

“用户token的表示激活有梯度”与“用户目标不计直接损失”同时成立：后续助手分数依赖用户上下文，所以回答损失仍可沿注意力反传到用户表示。实验捕获的是查表后的中间激活梯度，避免将共享输入/输出表示表上的梯度误当作输入上下文贡献。

没有保存这次更新后的权重，不覆盖第五十课最佳状态。只记录docs/training_runs/lesson51.json，源文件前后SHA相同。单批损失下降仅说明本批参数确实更新，不能证明泛化、不会过拟合或能chat；本课没有在SFT验证集上选优，没有额外生成并挑选“好看”的回答。

本课6.214679是两条对话的助手目标训练损失，上一课4.430704是完整预训练验证损失。数据范围、目标掩码与用途不同，不能用这两个数的大小判断切换SFT后模型变好或变坏。
