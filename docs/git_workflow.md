# Git 仓库管理约定

远程仓库：https://github.com/codesknight/playATryModel

## 分支与提交

- `main` 保存检查通过、可运行的学习进度。
- 每次完成一个可验证的小目标再提交，例如数据检查、词表建立、一次训练实验。
- 提交时把相关代码和对应学习笔记一起保存；尚未完成的任务在笔记中明确标注。
- 小型学习步骤可以直接提交到 `main`。较大实验使用 `experiment/主题` 分支，通过比较结果后再决定是否合入。
- 不自动创建未完成的练习代码，也不把“已布置”记作“已掌握”。
- 每课检查通过后，提交本课完整代码、相关数据和学习笔记，推送 GitHub，检查自动检查结果，并向学习者报告提交号与同步状态。

提交说明使用简短的类型和描述：

```text
feat: 完成原始文本检查脚本
fix: 修正训练样本的目标偏移
docs: 记录第一课结果和换行计数问题
chore: 更新依赖和仓库配置
```

## 日常同步

下面的文件名是第一课完成后的示例，文件存在并验证后再执行。

```powershell
git status # 查看当前分支和修改的文件。
git diff # 查看尚未暂存的文本修改。
git add scripts/learn/01_inspect_data.py data/corpus docs/learning_notes.md # 暂存第一课的代码、实际采集语料和笔记。
git diff --cached # 检查本次准备提交的具体内容。
git commit -m "feat: 完成第一课数据检查" # 在本地保存这一课的完整进度。
git push origin main # 把已提交的进度同步到 GitHub。
```

换电脑或从其他地方修改过仓库后，先确认本地没有未处理修改，再同步：

```powershell
git pull --ff-only # 只允许直接前进，有分叉时停下来检查。
```

如果推送被拒绝，先检查远程变化并处理差异，不使用强制推送覆盖历史。

## 数据与权重

- 小型、自写的教学文本可以和代码一起提交，保留能复现实验的数据版本。
- 采集外部数据时记录来源、获取时间和使用许可，确认可以分享后再纳入仓库。
- `.env`、Python 缓存、虚拟环境、日志和常见编辑器本地配置不提交。
- 仅将现有微型示例权重纳入 Git；后续实验权重默认忽略。
- 增加更大模型时，先确定独立的产物存储方案，避免不断增加 Git 历史大小。

## 自动检查

`.github/workflows/check.yml` 在推送和 Pull Request 时运行：

1. 安装 NumPy 依赖。
2. 编译检查 Python 文件的语法。
3. 加载示例权重并生成短文本。
4. 用两步训练检查训练入口，再加载新权重生成文字。
5. 运行已完成的第一课数据检查和第二课清洗，比较清洗输出与仓库版本是否一致。

现有模型示例位于 scripts/example/，练习位于 scripts/learn/，移动目录后需要同步更新运行命令和根目录计算。

这些检查只判断基本流程能否运行，不衡量生成质量。以后实现正式测评后，再加入相应检查。
