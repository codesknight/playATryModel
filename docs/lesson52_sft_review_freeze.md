# 第五十二课：逐条审核对话，冻结可用范围

本课不增加模型步数。目标是把“文件能读、长度能放入”与“回答值得学习”分开，并用可重建的数据版本记录判断。第五十一课接通了SFT计算；本课实际检查原训练及验证文件的格式与长度，助手逐条阅读26条候选的完整消息，保存接纳、拒绝和待核实理由，冻结一个4条训练、2条验证的小型审核子集。样本少且全为英文，尚不能启动面向中文聊天的正式SFT。

这里的逐条审核由助手进行，不宣称经过独立领域专家或真人标注团队复核。接纳表示本次按明确适用条件审阅后可保留，仍不是事实无误、没有遗漏的保证。固定原来源为[jingyaogong/minimind_dataset](https://huggingface.co/datasets/jingyaogong/minimind_dataset)，提交312afb4f76391145c6902f765bb51691c09a12f5，沿用第四十八课来源归属与混合许可；不把仓库代码许可当作所有数据的统一许可。

## Block 1：先查技术条件，不能偷换为内容合格

prepare_sft_review.py读取原sft_train.jsonl与sft_validation.jsonl，不打开测试正文。每条完整会话通过上一课encode_dialogue检查角色、下一token目标、保留标记冲突及最大上下文256；完整输入超长时记over_context，不截掉回答，也不认定为坏数据。

|原划分|记录总数|完整超长|格式及长度可送审|
|---|---:|---:|---:|
|train|2842|2322|520|
|validation|364|302|62|

训练集能直接放入当前模板的比例为520/2842≈18.30%。这是完整会话长度条件下的结果，不代表其余81.70%语义错误。较长会话中可能包含可用轮次，但需要设计保持前文依赖、完整答案和来源组归属的新分段版本，本课不静默截断。

## Block 2：固定审核队列，不只挑开头几条

对每个有技术可用候选的来源块，训练取最多4条，验证取最多2条；不足配额则全取，不复制补数。固定种子字符串lesson52:20261125与split、id组成摘要，按SHA-256排序：

```python
candidates.sort(key=lambda row: sha(f"{SEED}:{split}:{row['id']}".encode("utf-8")))  # 为同一来源块建立可重建顺序。
queue.extend(candidates[:quota])  # 按明确配额取样，不因看过答案而更换队列。
```

最终队列训练18条、验证8条，保存在data/chat52/queue.json。固定种子不是全部复现条件，原文件SHA、算法、筛查规则、BPE及上下文也要相同。新增语料应建立新版本，不覆盖原文件或借验证样本补训练数。

这是来源块分层、仅完整短会话的限额抽查，不是全库随机代表性抽样。各块可用条数不同，不能把此次拒绝比例直接当全数据错误率；也不能由未抽到某类任务推断原库不存在这类任务。

## Block 3：三种内容决定

reviews.json对26条完整会话逐条给出split、id、text_sha256、decision、reason_code与reason。

|决定|含义|是否进入冻结子集|
|---|---|---|
|accept|内容与任务基本相符，已按记录条件检查|是|
|reject|发现答非所问、内部矛盾、虚构经历或破损任务等明确问题|否|
|hold|具体事实、术语或表达需进一步核实或修订|否|

hold不等于已证明错误。例如引用的标准、人物资料和历史数字，本课未独立核实就不批准；不需要为凑训练量把不确定的回答当正确，也不应把“尚未核实”写成“事实错误”。涉及具体药物用途的候选也排除本课范围，此处不提供用药结论。

实际审核结果：

|原划分|审核|接纳|拒绝|待核实|
|---|---:|---:|---:|---:|
|train|18|4|8|6|
|validation|8|2|3|3|

接纳训练标识为sft:01:00389（理想气体方程移项，物理体积V>0）、sft:01:00380（条件表达式转英语句子）、sft:03:00127（SQL按条件查询，定位单行需id唯一）、sft:04:00075（24−12−6=6的算术程序）。两条验证标识为sft:01:00463（假设对话的耐心回应）与sft:02:00176（含糊GLM问题先澄清）。它们均为原英文内容，没有翻译或改写。

几类拒绝示例：标题大小写结果与后续解释自相矛盾；题面没有提供要改写的句子却给出无关鼓励语；助手把近期看电影、与朋友聊天当作真实经历；残缺数字题被强行赋予唯一规律。多轮会话存在不合格轮次时本课整体不接纳，不悄悄只摘出其中好听的两句；后续若修订需建立新版本并检查依赖。

## Block 4：冻结意味着保存什么

freeze_sft_review.py先调用validate_reviews，要求候选集合与决定集合完全相同，重复审核、漏审、正文摘要变化均失败。源文件SHA由队列重建检查，接纳的原会话完整输出，不换split、不改group_id、不修改答案：

```python
if decision["decision"] != "accept":  # reject和hold都不能直接拿来训练。
    continue  # 未核实不会被当成默认接纳。
selected.append(row)  # 保留原完整消息、分组和来源字段。
```

结果在data/chat52/frozen_v1：train.jsonl、validation.jsonl及manifest.json。训练4条/4组/735个助手目标，验证2条/2组/338个助手目标；目标数使用原6400词BPE。两集合原组无交集，但原去重分组本身是启发式，不能保证绝无语义近重复。

清单保存来源、队列、决定和词表SHA，以及输出文件SHA和字节数。重复运行应完全一致；修改决定或筛查逻辑时应另建版本，不覆盖frozen_v1。旧chat48、chat51与模型文件均不改变。检查训练和验证内容质量不等于训练模型；使用相同内容准则排除不合格验证答案可以，但不根据模型损失挑选容易验证题，也不将验证答案挪到训练集。

## Block 5：为何显示“不允许正式SFT”

本课为后续设置一个初步课程门槛：至少64条经审训练会话、16条经审验证会话，两边中文覆盖会话比例均至少50%。这不是统计学证明或训练出可用chat的充分条件，后续仍需有预算的实测和固定未见问题评估。更改此策略必须记录新版本，不能为让False变True临时降低标准。

中文覆盖的统计代理是常用汉字占正文字符比例≥20%，不是精确语言识别，更不是内容质量打分。实际接纳的4条训练和2条验证该数均为0。数量少、全英文，会偏离用户的中文聊天目标，所以manifest的formal_sft_ready=False，列出四个不足项。这是筛查发现问题的正确结果，不是脚本崩溃。

本课没有正式SFT训练入口，门槛供后续训练器检查，不宣称能拦截任意另写的脚本。预训练正式累计仍2020，上一课一次副本诊断也不会变成正式SFT检查点。没有新增权重、测试指标或聊天能力结论。
