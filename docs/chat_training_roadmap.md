# 从续写模型走向小于1GB的聊天模型

初版日期：2026-11-18；实际进展更新：2026-11-24。学习者明确提出参考MiniMind，训练一个小于1GB并能聊天的模型。默认延续从零学习和训练的主线；每行代码有直白中文注释，先分块讲清，再由学习者实操。本页保留规划时背景与后续路线；2026-11-24已实际完成30M首段预训练试验，见[第四十八课](lesson48_data_tokenizer_pilot.md)，仍未进行SFT或达到可用chat能力。

## 初版现状与新目标（2026-11-18规划背景）

当前已实际训练的是168万参数、字符级、128字上下文的Transformer续写模型，六轮4896更新。它可以预测和续写，但没有对话角色训练，固定样例仍重复、人物串书。仅加一个聊天输入框不能让它学会回答，继续训练小说也不能替代对话监督。

1GB沿用原项目定义：最终导出的推理模型权重文件总大小小于1000000000字节。不是1GB显存，不是Python环境、原始语料、优化器检查点都加起来不到1GB。实际导出后必须测量文件字节，估算不代替验收。FP32、FP16、BF16每参数的常见存储分别为4、2、2字节，不必为满足此目标先做4bit量化。

最小聊天目标是简单中文问题有相关回答，能按要求简短回答，能使用保留在上下文内的多轮历史，且能在助手消息结束符处停止。不是承诺达到大型商业聊天模型的知识、推理或可靠性。

## 参考项目核验

参考[jingyaogong/minimind](https://github.com/jingyaogong/minimind/tree/2de2308d71750b44d56fd28cd8756239eee18957)，核验版本2de2308d71750b44d56fd28cd8756239eee18957，提交时间2026-11-18 06:08:54 UTC。它当时的主线是MiniMind-3稠密约64M，旧版26M不等于当前默认配置；不同版本的权重、模型结构、分词器不能混用。

根据[模型源码](https://github.com/jingyaogong/minimind/blob/2de2308d71750b44d56fd28cd8756239eee18957/model/model_minimind.py)，主线使用RMSNorm、RoPE、GQA、SwiGLU和共享输入输出表示表，并包含Q/K归一化。[对话数据处理](https://github.com/jingyaogong/minimind/blob/2de2308d71750b44d56fd28cd8756239eee18957/dataset/lm_dataset.py)将对话按模板编码，只对助手区域设置有效labels；[SFT入口](https://github.com/jingyaogong/minimind/blob/2de2308d71750b44d56fd28cd8756239eee18957/trainer/train_full_sft.py)在预训练权重上执行监督微调。这些实现是结构与管线的参考，本仓库尚未复制或实现完整MiniMind模型，也未下载它的模型权重。

项目README所称约两小时，指RTX 3090上SFT一轮的项目实测条件，不是本机从零完成分词器、预训练、SFT和测评的总时长。RTX 3080 10GB不能照搬3090 24GB的默认批大小。

## 候选结构与参数预算

先选稠密约30M做硬件试跑，64M作为后续候选，不先引入MoE、工具调用、强化学习和思考标签等额外目标。以下为初版预算配置。后续30M已实际创建并完成1020次预训练更新，64M尚未创建；两者都没有SFT聊天验收结果。

|候选|层数/宽度|查询头/KV头|词表|参数数|FP32权重|FP16/BF16权重|
|---|---|---|---|---:|---:|---:|
|首选预算|8/512|8/4|6400|30025216|120.10MB|60.05MB|
|后续候选|8/768|8/4|6400|63912192|255.65MB|127.82MB|

公式：设宽度D、查询头H、KV头K、每头维度d=D/H，SwiGLU中间维度F=ceil(D×π/64)×64，词表V，层数L。

```text
每层注意力矩阵参数 = 2×D×H×d + 2×D×K×d
每层SwiGLU参数 = 3×D×F
每层归一化参数 = 2×D + 2×d
总参数 = V×D + L×(注意力矩阵参数+SwiGLU参数+归一化参数) + D
```

不含线性偏移；Q/K归一化的2d已计入。RoPE缓存不是可学习参数，文件封装和元数据还有额外开销。词表6400只是预算假设，需要在正式分词器阶段确定，变更后重算参数。30M配置不能直接加载旧版26M或当前64M预训练权重。

FP32参数、梯度、Adam的m/v粗略共16P字节：30M约480MB，64M约1023MB。保存参数加m/v约12P字节：30M约360MB、64M约767MB；这些均不含激活、logits、混合精度额外状态、显存工作区和缓存，所以不能仅凭该数断言10GB训练一定能放下。

可执行核算见scripts/experiments/estimate_chat_budget.py，机器可读方案见docs/plans/chat_model_budget.json。它们只核算预算，不下载、创建或训练网络。

## 逐步实施与验收

|阶段|实际要做的工作|进入下一阶段前的证据|
|---|---|---|
|1 对话格式|完整会话JSONL、角色标记、助手损失掩码、结束符；已有教学演示|首字目标对齐、用户目标被忽略、坏样本被拒绝|
|2 分词与数据|选择或训练约6400词的子词分词器；固定许可来源、清洗去重、会话/模板分组和独立划分|编码往返、未知率与压缩率、固定模板和分词器版本、训练验证不重叠|
|3 模型逐块实现|RMSNorm、RoPE、GQA、SwiGLU、因果Transformer；后续再加KV cache|参数量实数核对、未来不可见、有限梯度、独立保存重载|
|4 硬件试跑|30M、序列256、微批1、梯度累积8，先最多20次优化器更新/300秒|实测峰值显存、有效token每秒、有限损失、恢复后的下一批一致|
|5 预训练试验|广泛而干净的中文文本；先最多1000次优化器更新/1800秒，达到任一上限收尾|同范围验证优于自身字频基线、固定生成、预算与恢复报告|
|6 SFT试验|从已验证预训练检查点开始，使用有来源的真实多轮指令/回答数据；首轮同样设小预算|只对助手目标算损失，固定未见问题和追问，完整记录失败|
|7 扩大训练与聊天入口|依据实测tokens/秒决定后续每阶段预算，保留best和last；命令行多轮chat|上下文截断规则、消息结束停止、完整聊天记录、实际导出权重小于1GB|

初版时仅阶段1演示完成。2026-11-24已完成阶段2的有界来源采样/BPE准备、阶段3模型实现、阶段4硬件试跑及阶段5首段预训练。阶段6 SFT及可用聊天验收尚未完成；数据内容质量仍有抽查发现的局限，详见第四十八课。300秒和1800秒是后续建议预算，尚未运行；训练截止按批次边界检查，验证保存收尾另计。长期预训练需在短跑结果后，明确新的token、时长和轮数预算。此处不把千步小试验当作已经能聊天的训练量。

混合精度初步选FP16 autocast配合GradScaler，主参数保持FP32；是否适合本卡由试跑确认。发生显存不足先缩短序列或降低微批，不能靠减少导出文件大小解决。梯度累积时多个微批才执行一次step，不再每个微批清梯度；有效token数不同的微批需要按目标数加权，不能无条件平均各微批平均损失。

## 对话语料的接入方式

已有四书和TinyChineseStories继续作为语言与格式教学材料，不能代替问答指令语料。MiniMind README列出的pretrain_t2t_mini和sft_t2t_mini分别是GB级数据；本次没有下载它们，也未把代码Apache许可视为所有训练数据的统一许可。下一阶段先核对选定文件的数据卡、上游来源、许可、固定版本和格式，再按明确下载/token预算采样。不要把首几条随机格式样本当作代表性训练集。

正式对话按完整会话和来源模板组划分，重复或改写样本尽量同组；问答中的用户文本虽不作SFT目标，也要参与去重。分词器和训练集统计不使用测试内容。先分组留出验证和最终测试，再做超参数实验。

可以采用统一messages字段，每条消息为role和content。本课data/chat_demo/messages.jsonl仅两条原创格式示例，不是训练集或测评集。MiniMind数据使用conversations字段，后续需要显式转换，不能假装字段名天然一致；其工具/思考格式先不接入普通聊天教学。

SFT时输入仍包括用户与系统文本，但对应目标设置-100；只监督助手正文及其结束标记。损失掩码也必须随目标一起错一位。屏蔽提示目标不代表提示不参与模型计算，回答损失的梯度仍可通过注意力传到用户输入所涉及的参数。

## 怎么判断真的开始会chat

固定未参与训练的开发问题和多轮追问，覆盖问候、概念解释、简短指令、同上下文回忆。统一温度、最大生成长度与模板；记录答非所问、重复、首轮是否相关、追问是否保持上下文、结束符是否正常。先保留所有原始回答再人工评分，不能只展示最好的两句。开发问题用于选优，最终测试仅在冻结配置后使用。

未知问题的表现比训练问答复述更有价值；会打印一问一答界面、SFT loss下降、记住两条格式样例，都不等于具备可用聊天能力。未来可在同一结构/分词器下比较预训练检查点与SFT检查点的固定聊天表现，而不是直接用旧RNN/不同词表的交叉熵比较。
