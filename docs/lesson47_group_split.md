# 第四十七课：按group_id划分并冻结版本

## 什么时候开始训练聊天模型

已有168万参数Transformer实际完成六轮4896次更新，但它仍是续写模型。30M聊天模型目前只有结构预算，尚未实现或训练。接下来按实操里程碑推进：

1. 本课：完成分组划分、覆盖检查、版本和组映射保存。
2. 下一次实操：接入经来源审查的正式语料，准备固定分词器与对话模板；小规模数据先跑通，不要求先完成全部理论问答。
3. 随后的实操：逐块搭建30M结构并做最多20次更新/300秒的硬件试跑；检查通过后，当次启动首段最多1000次更新/1800秒预训练，达到任一上限收尾。
4. 根据真实验证、有效token吞吐和显存扩大预训练，再进行助手回答SFT与固定多轮聊天评估。

因此，安排是在本课之后两次实操中开始新模型的真实训练，前提是正式语料、分词器和模型检查能通过；若遇到数据或环境问题，要先修正并如实说明，不把计划写成已完成。这里估计的是何时启动训练，不是何时保证能流畅聊天。预训练不等于SFT，千步试跑也不等于足够的语言训练量。训练批次截止后的验证和保存收尾另计。

## 先复盘刚才的回答

学习者答对：答非所问不能直接作为合格SFT样本；重复100次不会产生100份独立知识；训练验证重复会泄漏；只改名字不等于独立模板；组数比例不必等于样本比例；新增数据后即使种子不变结果也可能变；新增样本沿用已有验证组；验证内容变后不能当作同一把尺子比较。

纠正点：重复样本不表示梯度不变，梯度还依赖当前模型参数；重复过多会改变样本训练权重并增加记忆/过拟合风险，但不必然过拟合。同组被分到验证集时，学习者起初答其余样本进入训练集，解释后对测试组正确答相同测试集。新增数据影响的是组列表、长度、排序和边界，不一定是统计分布改变。上述是问答进展，不是已独立完成代码的证明。

## 本课目标与文件

脚本：scripts/learn/27_split_chat_groups.py。示例：data/group_demo/samples.jsonl。预跑产物：data/group_demo/splits_v1。示例为助手原创12条短对话、10个已给定分组，只用于教学，不用来训练或测评；group_id是人工指定的，本脚本不会自动识别全部相似文本。正式语料在划分前仍需要格式、内容和去重/分组审核。

同一组g00中有三个只改名字的苹果题，其余九组各一条。种子42下预期结果：

|集合|组数|样本数|正文字符数|
|---|---:|---:|---:|
|train|8|8|100|
|validation|1|3|81|
|test|1|1|11|

这里字符数是全部消息正文之和，包括用户问题，不包含角色标记，也不是分词器token数。按组数8/1/1划分，样本数8/3/1并不矛盾。

## Block 1：先排序，再用独立随机数生成器打乱

```python
groups = sorted({row["group_id"] for row in samples})  # 去重并排序，固定打乱前的组列表。
random.Random(seed).shuffle(groups)  # 使用独立固定种子，不干扰模型或其他模块的随机状态。
train_end = len(groups) * 8 // 10  # 前80%的组分给训练集，按整数向下取整。
validation_end = len(groups) * 9 // 10  # 到90%的边界之前分给验证集，其余是测试集。
```

本演示至少10组，避免小组数使10%取整为空。固定种子还需要固定数据与方法；不能保证新增数据后原划分不变。

## Block 2：建立组到集合的映射

```python
mapping = {group: "train" if i < train_end else "validation" if i < validation_end else "test" for i, group in enumerate(groups)}  # 每个组只确定一次集合。
partitions = {name: [] for name in ("train", "validation", "test")}  # 创建三个独立容器。
for row in sorted(samples, key=lambda item: item["id"]):  # 固定输出的记录顺序。
    partitions[mapping[row["group_id"]]].append(row)  # 根据组归属放入样本，不对每条单独随机。
```

查看group_to_split.json，应看到g00属于validation，其三个样本都在validation.jsonl中。

## Block 3：检查与保存

脚本核对三个集合的group_id两两无交集、样本id不重复且覆盖完整。保存文件包括：

- group_to_split.json：已有组的归属映射。
- train.jsonl、validation.jsonl、test.jsonl：完整会话记录。
- manifest.json：输入SHA-256、种子、按组比例、实际统计和各产物SHA-256。

文件通过UTF-8字节写入并固定LF换行，避免此前清单哈希遇到的Windows/Linux换行差异。输入哈希针对实际原始字节，哪怕只改变JSON空白也会被识别为新的来源版本；这不等于空白变化是脏数据，而是版本指纹的定义如此。

首次运行创建版本，后续同输入运行只核验，不重新写文件。若输入或种子改变，必须指定新输出目录；若已有划分文件被修改，脚本报错，不静默覆盖。它还不是自动接收增量语料的程序：保留旧映射处理新组的增量模式将在需要时另外实现。
