# 第五十课：完整恢复30M模型并有界续训

本课不是重新训练一个随机模型，也不是把FP16推理文件当作断点。助手按授权代跑本课实验，学习者实操先使用只读脚本观察真实完整状态；不将助手代跑记为学习者已经独立实现训练器。

## Block 1：先检查来源文件

学习脚本scripts/learn/30_inspect_resume_state.py默认读取model/lesson48/last_train.pt，只使用CPU，不创建网络、不占用CUDA，也不更新参数。完整文件是Release附件，不会因为克隆Git仓库就自动获得；本地缺失时从第四十八课Release下载，不能替换为约60MB的pretrain_fp16.pt。

助手预跑的来源信息为：累计更新1020、所有参数的AdamW累计步数均1020、已处理2088744个有效目标、GradScaler缩放1024、学习率0.0003。第0轮微批偏移为8160（均从0计数），下一组窗口编号为[11280,2087,1234,2785,9349,1222,6051,7422]。

这里是训练流的窗口编号，不是6400词表中的token编号。第1020次更新已经完成，因此恢复后下一次成功更新是1021，不重做1020。检查脚本的预览也使用临时游标，不修改正式状态。

## Block 2：恢复什么，为什么

实际续训入口scripts/experiments/continue_chat_pretrain.py复用check_chat_resume.py的restore函数：

```python
model, optimizer, scaler, state = restore(source_path)  # 完整恢复FP32参数、AdamW、Scaler及随机状态。
cursor = dict(state["cursor"])  # 继续读取上次尚未处理的微批，不从第一窗重来。
step = state["step"]  # 累计更新1020，不在新阶段清零。
```

恢复函数先检查语料清单、分词器和编号流的SHA-256。模型结构按保存配置重建，参数完整load_state_dict；优化器必须load_state_dict恢复m、v和各参数累计t；GradScaler也要恢复scale与增长计数。CPU/CUDA随机状态一起恢复。

本课进一步限定来源SHA-256等于第四十八课报告中的真实完整状态，不把另一个“看起来也是1020步”的文件混入实验。复现后的完整验证损失5.336842与原起点一致，先验证再更新。

只加载模型参数只能延续预测函数，不能保证延续相同更新轨迹。只恢复m/v而丢掉数据游标也会改变接下来学习的窗口。FP16导出已经舍入且没有优化器历史，不能代替本课FP32完整状态。

## Block 3：新增计数与累计计数

保持语料、BPE、结构、上下文256、学习率0.0003和8微批累积不变。每新增200次更新评估相同388180个验证目标，并对三个固定开头分别生成贪心与固定种子的top-k续写。

预算在运行前设定：最多新增1000次成功更新，或阶段1800秒，先到者停止启动新累积组。恢复加载和起点验证在阶段计时前，阶段内的周期验证/保存包含在phase_seconds中；截止后的收尾验证/保存以及最终导出复核另计，不是进程硬截止。

累计步数=来源1020+本阶段成功更新数。微批不是step；一个成功更新仍需累积8个微批。被GradScaler跳过的溢出尝试不增加成功step，也不推进正式游标。

旧训练流共11854窗口，来源已经处理8160个，所以当前轮还剩3694微批。剩余微批用完后轮号增加，offset从0开始，并按数据种子248加新轮号重建排列。跨轮不会初始化模型，不会清空AdamW历史，也不会重置累计step。某一累积组可能横跨两轮，但仍按本组真实目标总数归一化。

来源实际已经见过2088744目标而非1020×2048，差异来自40目标尾窗。后续也必须逐窗口统计，不能用固定乘法代替。

## Block 4：保存最佳、最后与推理文件

新产物放model/lesson50，旧model/lesson48不覆盖。每个检查点保存last_train.pt完整进度；严格改善验证损失才替换best_train.pt，并导出约60MB的pretrain_fp16.pt。旧起点也参加最佳选择，训练更久不自动意味着更好。

完整状态继续使用chat_lm48_train_v1这个已验证的格式标识；其中48是历史格式版本字符串，不是新的累计步数或当前课程号。新增parent_checkpoint_sha256标明来源链。data/chat48仍是本课使用的冻结数据版本，不因进入第五十课而重新划分。

训练报告docs/training_runs/lesson50.json保存全部候选、阶段新增计数、累计计数、游标和真实数据顺序指纹。FP16导出另做完整GPU验证，CI仅复算明确记录的八窗子集，不冒充完整CPU验证。完整恢复核验仍只在副本中更新，不增加正式训练计数。

大型完整状态通过Release标签lesson50-pretrain-pilot交付，推理文件在Git中。完整附件的远端SHA与发布状态以lesson50_assets.json为准；若best与last不同则分别发布，相同内容不重复上传。
