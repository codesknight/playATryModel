## Block 3：从字符词表进入ByteLevel BPE

实现见scripts/experiments/prepare_chat_tokenizer.py，实际环境tokenizers==0.22.2。分词器也是需要训练的统计规则，但不是本课神经网络参数的梯度训练。

BPE从UTF-8字节表示出发，反复合并训练正文中频繁相邻的片段。常见汉字、词片段和英文单词可能合成一个token，稀有字或表情可能拆成多个字节片段，不再是一字一个编号。

词表6400，包括256个基础字节表示和8个特殊符号，另有训练学得的合并。仅pretrain_train和sft_train正文参与词表统计，不用验证/测试来补词。初始字节全集让未见字符也可分解，所以未知率0只表示编码覆盖，不表示模型理解每个生僻字。

|特殊符号|编号|用途|
|---|---:|---|
|pad|0|右侧补齐|
|bos|1|预训练文档起点|
|eos|2|预训练文档结束|
|system|3|将来的系统消息头|
|user|4|将来的用户消息头|
|assistant|5|将来的助手消息头|
|end|6|将来的单条聊天消息结束|
|unk|7|未知符号，正常ByteLevel编码不应出现|

实际保存的符号拼写为尖括号形式，如 `<|bos|>`。这套词表与MiniMind原词表、旧课字符词表都不是同一套切分规则；即使大小都是6400，也不能互换已有权重。

示例“春风又起，Hello🙂”有11个Unicode字符，当前编码为9个token，整体解码可以完整恢复原文。不要把单个字节token独立解码后再拼接；一个token可能只是某个UTF-8字符的部分字节。

预训练训练正文编码后，加上BOS/EOS共有3034409个token，正文token/字符比约0.6304。保存为uint16的npy，不使用pickle。验证按每篇文档独立切256位置，保留尾段，共2120窗、388180个有效目标，未知token为0。生僻字、繁简体、中英混合、表情和换行的整体往返及分词器重载均检查通过。

## Block 4：打包、目标与梯度累积

训练把BOS＋正文＋EOS连接成一个训练流，再取256目标窗口；窗口可以跨训练文档，这是流式打包，模型会看见边界符。验证按文档独立从BOS开始，没有把验证文档彼此接成前文。两种方式都在同一冻结口径下比较各检查点。

每个微批1窗口，一次优化器更新累积8个微批。完整窗口每组2048目标；如果包含只有40目标的尾窗，则为7×256＋40=1832。因此代码先累计这8个微批的有效目标数，每个微批使用loss_sum/组内有效目标总数反向传播，不能无条件平均各微批均值。

顺序为：组开始zero_grad → 八次前向及缩放backward → unscale → 全局梯度裁剪1 → scaler.step → scaler.update。溢出被跳过不能算一次真实更新；代码重试同一组且有次数上限。本次记录的跳过更新为0。

11854个打包窗口中最后一窗只有40目标。本次成功更新1020次，处理8160个微批，实际2088744个目标；不是把1020简单乘2048当作全部真实位置数。尚未遍历完整一轮，不能写成完成了一轮。下一数据游标为第0轮offset=8160。

## Block 5：30M结构与参数实数

实现见scripts/experiments/chat_model.py。参考MiniMind固定版本2de2308d71750b44d56fd28cd8756239eee18957的结构设计，独立用PyTorch实现，不下载模型权重，也不依赖transformers的模型封装。宽512、8层、查询8头、KV4头、每头64维，SwiGLU中间宽1664，RoPE位置缓存256。

RMSNorm使用均方根缩放而不减均值；RoPE旋转Q/K加入位置关系；GQA让两个查询头共享一组键和值；SwiGLU由gate/up/down三个矩阵组成。输入表示表与输出投影共享，线性层不使用bias，每层Q/K还各有64维归一化参数。

|部分|参数数|
|---|---:|
|6400×512共享表示表|3276800|
|每层注意力矩阵|786432|
|每层SwiGLU|2555904|
|每层两次RMSNorm与Q/K Norm|1152|
|8层合计|26747904|
|最终RMSNorm|512|
|实际总参数|30025216|

总参数与预算公式一致。FP32矩阵约120.10MB，FP16矩阵约60.05MB；实际PyTorch推理文件60079189字节，约60.08MB。完整训练状态360411451字节，约360.41MB，仍小于1GB，但超过GitHub普通Git的单文件100MB限制，所以发布为Release附件。

RoPE缓存不是可学习参数，保存时可重建。当前位置始终不能看未来；已用小配置修改未来输入而检查前文logits不变，同时检查所有参数收到有限梯度。没有因为换成新结构就保证语言质量。

## Block 6：实际试跑与首段预训练

预算：profile最多20次更新或300秒；通过后同一模型、同一优化器继续pilot，最多额外1000次更新或1800秒。初始完整验证在阶段计时前；阶段内的周期验证、生成和保存包含在phase_seconds中，截止后不启动新累积组，收尾验证/保存与最终导出复核可能另计；不是进程硬截止。
