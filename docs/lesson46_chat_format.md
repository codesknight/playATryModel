## 怎样理解这些数字

输入长度是编号数，不是可见汉字数。BOS、消息角色头和消息结束符各占一个编号。标签y与输入x等长，但不训练的目标位置用-100表示，因此全部输入位置数不等于有效损失目标数。

第一条包含两轮问答。两个助手回答正文分别有11与10个字符，每个回答再加一个消息结束符，共11+1+10+1=23个有效目标。显示的两个<|end|>分别结束各自的助手回答，不代表第一段回答后整个会话永久结束。

第二条助手回答正文18个字符，再加一个结束符，共19个有效目标。系统提示和用户问题仍保留在输入中，但不作为助手要生成的目标。

## 为什么输入问题，却不训练模型生成问题

假设一轮对话为：

```text
用户：你好
助手：你好！有什么可以帮你？
```

用户的问题是回答的条件。模型必须能看见它，才知道要回答什么。当前SFT目标则是学习在问题之后生成合适回答，所以用户正文对应的目标被忽略，助手正文及助手结束符参与损失。角色头由模板提供，在这个演示里也不作为训练目标。

可以概括成：输入保留整段历史；损失只选助手输出位置。未计入损失不等于从输入删除，也不等于与用户输入有关的参数没有梯度：助手答案的损失仍可通过注意力传播到处理用户上下文的参数。

## 目标和掩码都要错位

```python
x = ids[:-1]  # 每个位置输入当前已经读取的符号。
y = [token if train else -100 for token, train in zip(ids[1:], supervise[1:])]  # 下一符号目标和对应监督标记一起向左错位。
```

预测第一个回答字时，当前位置输入正是助手角色标记；目标应是回答首字，而非角色头。检查程序已单独核对首字对齐，并拒绝只有系统消息、以用户结束和以助手开头等无效示例。

初版示例中，默认无类别权重时，第一条平均损失的分母是23，第二条是19；合并为一个批次时，有效分母是42，而不是39+36=75。输入长度的差异不允许直接平均两个样本的平均损失。

## 问答纠正与学习者修改验收

以下记录更新前面的待答题与实操状态，初版数字作为历史保留；当前示例以本节修改后的数据为准。

学习者正确指出去掉输入问题会失去回答条件，经补充明确模型仍可能生成文字，只是无法针对问题回答。随后曾把目标-100理解为模型看不到问题，已讲清损失掩码控制评分位置、因果遮罩控制可见范围。学习者进一步提出被忽略位置不参与反向传播，已纠正：用户目标没有直接损失，但回答损失仍可经注意力影响处理问题的参数，学习者复答会影响。

代码理解：学习者最初不会计算[user角色比较结果]重复3次，解释后答对assistant正文2字符得到[True,True]。对用户结束符答Fasle，概念正确且已纠正Python拼写为False；对False目标答-100，对读到“好”后的目标答结束符编号5，对“好”加结束符的有效目标数答2，均正确。多轮第一段回答看不到未来第二个问题，答不会；SFT第二轮使用数据中的真实上一轮回答，答真实回答，均正确。上述是逐题作答与纠正证据，不宣称学习者已独立实现整个编码器。

## 新增重点：格式正确不等于回答质量合格

这次把回答改为“好”，是有意验证字符数量、结束符和监督掩码，不是为正式训练编写优质答案。“刚才我说了什么？”的回答“好”没有回答用户的问题，所以不应把这条修改后示例直接当作高质量SFT样本。数据仍标为format_demo_only_not_training_or_evaluation，没有拿来训练或测评。

格式检查只能确认角色顺序、目标对齐、有效目标和结束标记等结构；它不会自动判断事实正确、是否答非所问或是否适合正式训练。下一阶段接入正式对话语料时，需要在格式检查之外审查问答相关性、正确性、多轮一致性、重复与分组划分。
