## 怎样理解这些数字

输入长度是编号数，不是可见汉字数。BOS、消息角色头和消息结束符各占一个编号。标签y与输入x等长，但不训练的目标位置用-100表示，因此全部输入位置数不等于有效损失目标数。

第一条包含两轮问答。两个助手回答正文分别有11与10个字符，每个回答再加一个消息结束符，共11+1+10+1=23个有效目标。显示的两个<|end|>分别结束各自的助手回答，不代表第一段回答后整个会话永久结束。

第二条助手回答正文18个字符，再加一个结束符，共19个有效目标。系统提示和用户问题仍保留在输入中，但不作为助手要生成的目标。

## 为什么输入问题，却不训练模型生成问题

假设一轮对话为：

```text
用户：你好
助手：你好！有什么可以帮你？
```

用户的问题是回答的条件。模型必须能看见它，才知道要回答什么。当前SFT目标则是学习在问题之后生成合适回答，所以用户正文对应的目标被忽略，助手正文及助手结束符参与损失。角色头由模板提供，在这个演示里也不作为训练目标。

可以概括成：输入保留整段历史；损失只选助手输出位置。未计入损失不等于从输入删除，也不等于与用户输入有关的参数没有梯度：助手答案的损失仍可通过注意力传播到处理用户上下文的参数。

## 目标和掩码都要错位

```python
x = ids[:-1]  # 每个位置输入当前已经读取的符号。
y = [token if train else -100 for token, train in zip(ids[1:], supervise[1:])]  # 下一符号目标和对应监督标记一起向左错位。
```

预测第一个回答字时，当前位置输入正是助手角色标记；目标应是回答首字，而非角色头。检查程序已单独核对首字对齐，并拒绝只有系统消息、以用户结束和以助手开头等无效示例。

当前默认无类别权重时，第一条平均损失的分母是23，第二条是19；合并为一个批次时，有效分母是42，而不是39+36=75。输入长度的差异不允许直接平均两个样本的平均损失。
