# 第四十九课：验证梯度累积与大批更新等价

本课对应已经实际训练的30M模型，不追加长训练，也不修改既有模型、分词器或语料。助手预跑验证完成，学习者尚待运行提交。代码scripts/learn/29_gradient_accumulation.py每行有中文注释，默认仅CPU打印，不写权重或报告。

## 为什么要累积梯度

一次将大批输入送入模型，需要同时保存较多前向激活用于反向传播。拆成微批后，每个微批前向、反向并释放自己的计算图，但参数上的.grad保留并继续累加；最后才进行一次更新。这样减少同时保留的激活量，不能消除参数、梯度和优化器历史本身的内存。

本项目微批大小1、累积8个微批，每组执行一次optimizer.step。模型参数在这8个微批之间保持不变；它不是每次反向后立即更新的8次小批训练。无需retain_graph=True，因为每个微批是新建的独立计算图；也不要先把8个带图loss相加，最后才backward，那会让多个计算图同时驻留。

## Block 1：为等价比较固定条件

实验使用三个相同初始化的微型线性输出层，输入形状(8,3,3)，输出(8,3,2)，目标(8,3)。这里三维输入是模拟特征，不是Token编号；两类别是简化的输出词表，不是新语言模型。CPU float64减小舍入误差，没有Dropout、BatchNorm、梯度裁剪或混合精度等额外变量。

七个微批各3目标，最后一个微批1目标，另外两位置是-100：

```text
有效位置数：[3,3,3,3,3,3,3,1]
整组目标数：7×3+1=22，而非填充后的8×3=24
```

对照分支一次计算全部22目标的平均交叉熵并backward一次。两个累积分支都backward八次且step一次，只有损失加权方式不同。

## Block 2：正确累计损失和梯度

设微批i的有效损失之和为S_i，有效目标数n_i，整组目标数N=Σn_i。大批目标函数是：

```text
L = (S_1 + S_2 + … + S_8) / N
∇L = ∇(S_1/N) + ∇(S_2/N) + … + ∇(S_8/N)
```

因为求导具有加法线性，上式可以分八次反向传播，但必须使用相同参数计算，且每次都使用相同总分母N=22。

```python
optimizer.zero_grad(set_to_none=True)  # 一组开始时清除旧梯度。
for index in range(8):  # 同一组八个微批，期间参数不更新。
    logits = model(x[index:index + 1])  # 只保留当前微批的计算图。
    loss_sum = F.cross_entropy(logits.flatten(0, 1), y[index:index + 1].flatten(), reduction="sum")  # 有效目标损失先求和。
    (loss_sum / total_valid).backward()  # 除以整组有效目标数，累加梯度。
optimizer.step()  # 八次backward之后只更新一次。
```

## Block 3：为什么直接除8会错

错误示范计算的是各微批均值的平均：L_bad=Σ(S_i/n_i)/8。最后一个微批只有一个目标，却得到整组1/8的权重；正确权重应为1/22，相差2.75倍。其他3目标微批每个目标权重为1/24，也与正确的1/22不同。

只有在各微批有效目标数相同、并满足其他等价条件时，微批平均损失再除累积次数才等价。不能仅凭物理张量长度相同就认为有效长度相同。

实际30M管线中，一个累积组若包含7个完整256目标窗口和40目标尾窗，N=7×256+40=1832，尾窗只应占40/1832约2.18%的目标权重，而非12.5%。train_chat_pilot.py的update函数正是用reduction=sum和整组valid归一。

## 对应到真实混合精度训练

真实代码在整组开始清梯度；每个微批使用scaler.scale(loss_sum/N).backward；整组结束才unscale，再按总梯度范数裁剪，随后scaler.step和scaler.update。若溢出导致更新跳过，不能增加真实step。本次已有30M试验跳过次数为0，正式累计1020次更新不受本课三个微型更新影响。

梯度裁剪要在累积结束后统一做，每个微批分别裁剪通常改变结果。Dropout随机路径、BatchNorm跨样本统计以及混合精度舍入可能破坏严格逐位等价，因此不能把这个float64输出层实验推广成“任何大模型大批与累积必定逐位相同”。本项目使用逐token的RMSNorm、无Dropout，但FP16仍有数值误差。
